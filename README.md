## What is ALL-TOOLS?

ALL-TOOLS provides a collection of HTML utilities through a single, browser-accessible hub. It is intended to make frequently needed tools available with very little setup, whether the files are opened locally or placed on a lightweight web host.

Its structure is deliberately simple and modular. The HTML-first design keeps the project straightforward to browse and maintain while leaving room to add further utilities as the hub grows.

## Using the Hub

1. Load the main HTML page in your browser.
2. Select a utility from the hub interface.
3. Work with the selected tool without installing additional software.
4. To add another utility, place its HTML files within the existing structure and add a link from the hub page.

When deploying the project online, preserve the existing file paths. Consistent paths help the navigation continue to work and make future maintenance easier.

## Project Layout and Configuration

There is generally no separate configuration system. Customization is performed within the HTML pages, navigation references, and associated assets. To change the hub, edit the landing page or the utility pages it connects to.

Example structure:

    /all-tools-2026-hub
    ├── index.html
    ├── tools/
    └── assets/

In a typical installation, settings are changed directly in the project files rather than through a standalone runtime configuration file.

## Frequently Asked Questions

**How can I find newer versions?**  
Review the repository or follow the latest build link to check for the current release and newly added utilities.

**Is the hub expandable?**  
Yes. Additional tools can be integrated by following the existing HTML structure and linking them from the hub.

**Does it require a special runtime?**  
No. A browser is sufficient for local use. Online deployments only need a basic static web server.

**Where are customizations made?**  
Edit the relevant HTML files and any assets linked by those pages.

**What can I check when a utility fails to open?**  
Inspect the file paths, make sure the browser can reach the required assets, and confirm that deployment retained the expected directory structure.
